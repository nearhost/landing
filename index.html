Run it anywhere.
Open it here.

Nearhost is a terminal app that opens a project running on one of your other machines at a local https://myapp.test, over the SSH config you already have. You install nothing on the server, and cookies, OAuth redirects, WebSockets and hot reload behave as they do on localhost. A coding agent on that machine can use it too: it asks to add the project, open a preview or show you a plan, and you say yes.

$curl -fsSL https://nearhost.dev/install.sh | sh

Set up in three steps, with nothing to install on the server.

If ssh mini works without a prompt, Nearhost works. It reuses your SSH config, including ProxyJump, agents and keychain identities, and installs nothing on the remote machine.

01

Add a server

Pick a host alias from ~/.ssh/config or type user@host. Nearhost checks that it connects without a prompt and shows OpenSSH's own output if it doesn't.

Adding a server
02

Add a project

Point at a path. Nearhost reads its .env over SFTP, and with the official presets its Compose and Vite config, and proposes the ports: which one is the web app, which need a loopback forward, which to ignore.

Adding a project
03

Open it

It starts as soon as you add it: Nearhost adds a hosts entry, issues a certificate from its local CA and routes https://myapp.test through the SSH tunnel. WebSockets and hot reload pass through the same tunnel. Press o to open it.

What the tunnel handles: HTTPS, hot reload and WebSockets.

Real HTTPS, trusted once

Secure cookies, OAuth callbacks and service workers need HTTPS, so every alias gets a real certificate. Nearhost creates its own local CA on first run and you trust it once. No shared key ships in the binary, so nobody else can mint certificates for your .test names.

TLS and the proxy

Hot reload and WebSockets pass through

Nearhost can forward a dev server's port to the same number on your laptop. Asset URLs that point at localhost still resolve, so hot reload connects with the remote config untouched.

Dev servers and hot reload

Port discovery

Nearhost reads port variables from .env. Presets from a registry you choose to trust add Compose, Vite and Laravel Sail, and warn about port clashes and a missing allowedHosts before you start. For anything else, give it the web port.

How discovery works

Runs on your SSH config

Nearhost shells out to OpenSSH, so Include, Match, ProxyJump, agent forwarding and keychain identities apply. It stores nothing but the host name.

SSH transport

Local projects too

The local server needs no setup. Projects on your laptop get the same alias and certificate, so one tool covers the laptop and the servers.

CLI reference

How it compares to ssh -L, mkcert, local dev apps, VPNs and tunnels.

Nearhost is for your own machines and your own browser. It is the wrong tool for showing work to someone else.

ssh -L by hand

The same OpenSSH forwards, typed per port and retyped after every dropped connection, with no hostname and no certificate.

Nearhost keeps one supervised SSH connection per server, adds and removes forwards while it runs, and puts a trusted https://name.test in front.

mkcert

Creates a local certificate authority and the certificates it signs. The rest is up to you: a server or proxy set up with them, a hosts file entry, and for a project on another machine, an SSH forward.

Nearhost does all of that. It creates its own certificate authority on first run, so you do not need mkcert, and signs a certificate for each name you add.

VS Code and other editor port forwarding

Convenient while the editor window is open. You get localhost:port URLs, so cookies and OAuth settings differ from a named HTTPS origin.

Nearhost runs in a terminal, independent of any editor, and each project keeps the same HTTPS name every day.

Laravel Herd, OrbStack and other local dev apps

Herd serves PHP sites from this Mac or PC at .test. OrbStack gives each container on this Mac an HTTPS name under .orb.local. Both serve what runs on the machine in front of you.

Nearhost serves projects on this machine and on any other you reach with ssh, for any stack, at names you choose, on macOS and Linux.

Tailscale or another VPN or mesh network

Makes the machine reachable, which usually means an agent on every machine and a dev server that listens beyond localhost.

Nearhost installs nothing on the server. The dev server keeps listening on localhost and is reached over SSH.

ngrok or another public tunnel service

Built for sharing. Your traffic goes through someone else's relay to a public URL, usually behind an account.

Nearhost has no relay, no account and no public URL. Use a tunnel service when a client needs to see the page.

Fix ngrok assets that point at localhost

Your traffic stays between your machines.

Nearhost has no relay, no account and no public hostname. Your .test names resolve from a marked block in /etc/hosts that Nearhost owns, and requests travel over your own SSH connection to the server.

Questions before you install.

Does Nearhost install anything on the server?

No. Nearhost runs on your laptop and shells out to OpenSSH. It reads files such as .env over SFTP, and adds only a private ~/.nearhost folder holding a socket, so a coding agent on the server can reach it. It writes a .nearhostrc to your project only when you run nearhost export. The server needs SSH that connects without a prompt, with SFTP and TCP forwarding allowed, as most servers do.

Which operating systems does it run on?

Nearhost runs on macOS and Linux, on Apple silicon, Intel and ARM. The server can be any machine you reach with ssh: a desktop under the desk, a home server, a VPS or a VM. Linux needs one extra step to bind ports 80 and 443 and to trust the certificate in your browser.

Does it work with my framework?

Nearhost routes ports, so it works with any HTTP dev server, such as Laravel, Rails, Django, Next.js or Vite. It finds ports in .env, and presets add Docker Compose, Vite and Laravel Sail. For anything else, give it the web port.

Can I share a Nearhost address with someone else?

No. A .test name resolves from /etc/hosts on your laptop and its certificate is trusted only there, so the address works in your own browser and nowhere else. To show a page to a client, use a public tunnel service such as ngrok.

What happens when the SSH connection drops?

Nearhost keeps one supervised SSH connection per server and reconnects by itself. While it is down, the projects on that server show as degraded and requests get a 502. Once ssh works again, press r to reconnect straight away.

Is Nearhost free?

Yes. Nearhost is open source under the MIT licence, with no account and no sign-up. Install it with the shell script, Homebrew or npm.

Install Nearhost.

One static binary for macOS and Linux, on Apple silicon, Intel and ARM. The first run offers to trust its local CA, then helps you add your first project.
